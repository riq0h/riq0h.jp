数日前にアクセスした人は気づいていると思われるが、このたび弊サイトをリニューアルした。もともとミニマル志向だった外観にさらに磨きをかけ、タイポグラフィを強調したより論理的なデザイン体系に整えた。どんなに瀟洒で豪華絢爛なWebサイトもLLMに頼めば小一時間で出来上がる時代に、あえてこのような意匠を象ったのには明確な理由がある。

それはそもそも、世の中には見てくればかりでコンテンツに乏しいWebサイトが多すぎるということだ。なにも別に必ずしも上等なコンテンツがなければいけないわけではない。その主宰者ないしは組織の内実を表しめるものであれば、読み手は十分に楽しめる。にもかかわらず、流行りのフレームワークを使っただけの記事数が片手で数えるほどしかないプログラマのブログや、制作会社に丸投げしただけの上っ面だけ大層に動くコーポレートサイトが世の中には多すぎる。

Reactで組んだリッチなサイトでも、HTMLパワーを標榜する温故知新なサイトでも、まずはコンテンツを作らなければ話にならない。今も昔も、Webサイトでもっとも重要な要素は第一にコンテンツ、第二にコンテンツだ。そこで僕はまずは自分自身でそれを体現すべく、コンテンツが存在していなければ美しく存在できないデザイン、すなわち文字情報のみのデザイン体系を構築したのである。弊サイトはフォントの大きさ、ウェイト、階調差によってのみデザインされている。

## 逆相関のフォントウェイト

弊サイトのフォントは[bunny.net](https://bunny.net)から配信されている。フォントにはNotoを使っている。案外普通だな？ と思う人もいるかもしれないが、僕の知るかぎり分割ロードに対応していて、何種類ものウェイトを持っている多言語フォントはこれだけだ。弊サイトの表現には複数のフォントウェイトが欠かせない。

```css
--w-title: 300   /* 題字・記事タイトル・h2 */
--w-h3: 400      /* h3以下の小見出し */
--w-body: 400    /* 本文 */
--w-meta: 400    /* 日付・タグ */
--w-pager: 400   /* ページャ */
--w-footer: 400  /* フッター */
--w-strong: 600  /* 太字(本文中の強調のみ) */
```

ブログや記事のタイトルとh2見出しには300のウェイトが使われている。本文は400、太字は600。見出しに太字を用いる通常のWebサイトのセオリーとは異なり、活版印刷の文化に通じる逆相関のタイポグラフィ体系を採用している。殊に文芸誌・ファッション雑誌の文脈では、大きいフォントはそれ単体で視覚的階層を有していると考えられ、そこに太字を重ねるのは二重強調となりエレガントではないとの発想がある。

弊サイトはWebサイトでありながら懐古的な読書体験――なんの気なしに買った文芸誌の片隅に載っている、風変わりだがそこそこ読ませる記事――を目指しているため、このようなデザイン体系は自己認識と一致するところであった。以前も概ね同じフォントウェイトを採用していたが、微調整を経て歴史的な裏付けを得た格好となる。

## フォントの抑揚

弊サイトは本文・タグ・日付の主要なまとまりにおいてフォントサイズの比率が1.246、音楽比でいうところの長三度(1.25)の近似値を採用している。これはモジュラースケール理論と呼ばれるデザイン手法で、一定の数学的比率に基づいて文字サイズの寸法を段階的に決定する。聴覚的に心地よい比率は視覚的にも応用できるとの考え方で、黄金比(1.618)や白銀比(1.414)に加えて短三度(1.2)、長三度(1.25)、完全四度(1.333)などが存在している。

もっとも長三度の近似値を採用したのは意図的ではなく、デザインの過程で結果的にこの値に漸進していった形が実態に近い。最後の最後で当該理論を知ったが、図らずもデザイン理論に基づいた値になったことで設計上の秩序を手にしたと考えられる。今後、別の箇所で調整をする時もまずはこれらの比率から試していけば納得できる公算が高いからだ。

![](/img/464.png)

たとえば、まさにこのアプローチがOGP用のレイアウト(後述)で活かされている。Webサイトより小さく表示される場合が多いOGP画像では、本体と同じフォントサイズだと日付とタグ部分の可視性が芳しくなかった。かといって記事タイトルを大きくして比率を保つと、今度は日付とタグ部分が目立ちすぎてしまう。

そこで記事タイトルを基準に長三度(1.25)ではなく完全四度(1.333)の比率で調整したところ納得のいくバランスが得られた。このように、以前はあやふやだったフォントの抑揚に理論的根拠を導入したことで、より一層に強固な体系を獲得できた。

```python
class Parser:
    """Tokenize and evaluate simple expressions."""

    def __init__(self, source):
        self.tokens = tokenize(source)  # cached for repeated use

    def evaluate(self):
        if not self.tokens:
            return None
        return sum(int(t) for t in self.tokens)
```

また、これまでは既存のハイライトカラーを使い回していたコードブロック部分も、常体・斜体・太字と階調差でシンタックスを組む様式で完全モノトーンのハイライトを実現している。あたかもコンピュータ黎明期のモノクロ印刷を思わせるデザインだが、意外にもこれで8通りのパターンを持っており、他のハイライトカラーと比べても遜色ない表現力を備えている。

## 動的なOGP画像の実装

従来はfaviconでOGP画像を代用していたが、せっかくCIも自前で用意しているのでなにかしらの文脈を持った画像を生成したいと考えていた。もちろん決して派手な代物ではなく、ブログタイトル、投稿日、タグ、記事タイトルが把握できれば差し支えない。仕組みとしては以下の通りとなる。

まず、Hugo(弊サイトが使用している静的サイトエンジン)のカスタム出力フォーマットを表示させたい項目に追加し、専用のHTML(`ogcard.html`)を各ページに生成する。この中身は実サイトの上部分(ブログタイトル、投稿日、タグ、記事タイトル)を切り取った形をしており、基本的には本体と同じcssファイルを参照しているが、OGP画像用に各部位のフォントサイズは大きく調整されている。

次にCIサーバ上でビルドステップが開始されると`chromium`パッケージが導入され、画像撮影用のスクリプトが起動する。スクリプトは静的サイトエンジンでビルドされた各記事をローカル配信し、`ogcard.html`を見つけるたびに1200✕630のスクリーンショットを撮る。すべての画像を撮り終えると、誤アクセス防止のためにogcard.htmlは削除される。

万が一、スクリーンショットの撮影に失敗した場合は、あらかじめ用意した静的フォールバック画像(トップページ用のOGP画像を個別に保存しておいたもの)をコピーして処理を継続しつつ、スクリプト自体は完走させて後からエラーを報告する。最後にちょっとした小技として、生成したPNGファイルの角1ピクセルだけアルファ値を99%に落としている。これはTwitter/Xが不透明なPNGをJPEGに再エンコードして画質を劣化させる処理を防ぐための工程である。

なお、OGP用の画像はビルド時に[bunny.net](https://bunny.net)へアクセスして読み込んでいる。実サイトと同じ方式を維持することで見た目の再現度を向上させている。一連の動的生成と引き換えにビルド時間が5分程度伸びてしまったものの、総合的には納得のいくデザインを表現できたと思う。実際に見て気づいたが、OGP画像はただの情報ではなくWebサイトの意匠を予告するセルフブランディングでもある。広く衆目に晒している以上は自己演出に手間をかけて損はない。

## 終わりに

以上、記憶が正しければ5、6年ぶりくらいのリニューアルとなる。自己表現の土台が説明可能な形で象られているというのは、時に実用性を越えた力強さとなって表れる。それはコンテンツを作る側のモチベーションであったり、読む側に単なる情報以上のなにかを与えるきっかけであったりするかもしれない。インターネットは情報収集の場であるとともに、依然として飽くなき自己表現の場でもあると僕は信じている。

ちなみに、フォントは下のフッターリンクからゴシックにも変えられる。サイズとウェイトはどちらも同じだが階調には微調整が加えられている。最後に切り替えた方がLocalStorageに保存される仕組みなので好きな方を選ぶといい。
