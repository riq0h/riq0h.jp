詳細は伏せるがPanasonic製のやつを自由にいじれる機会を得たので色々試していく。おそらく病院に置かれている端末では主要なタイプの一つではないだろうか。従来の健康保険証が廃止されマイナンバーカード方式に事実上一本化された今日では、すでにかなり多くの人がこの端末に触れた経験があると思われる。

こんな豪勢な機械を全国の病院に購入させ、対応する管理ソフトウェアも導入させ、補助金まで総動員して半ば無理やり運用を開始したほどなのだから、きっと利用者にとってはさほどそうでなくとも病院や政府にとっては有用なことに違いない。そうでないと困る。幸いにして機械の扱い自体はとても楽で、ユーザ側の操作といえばカードを置いてボタンを押して、顔写真を撮らせて後はいくつかの質問に答えるくらいしかない。

これらの裏側では端末と繋がっているWindowsマシン上の管理ソフトウェアが受け取った情報をよしなに処理している。端末本体にもIoT用のWindows（Windows IoT Enterprise LTSC）が搭載されているが、実は情報を新たに格納できるストレージも単独でインターネットに接続する機構も備わっていない。それぞれのハードウェアは以下の種類で構成されており、Windows側からは情報端末ではなく外付けディスプレイとして認識される。

```
| デバイス               | VID:PID     | GPIO   | 用途                     |
| ---------------------- | ----------- | ------ | ------------------------ |
| Sony RC-S634/UA        | `054c:06c2` | GPIO 1 | NFC/FeliCaカードリーダー |
| Ricoh KBCR-S03MU       | `05ca:18e8` | GPIO 2 | OCRカメラ (UVC)          |
| Futaba TouchController | `1008:1039` | GPIO 3 | タッチパネル             |
| Intel RealSense D415   | `8086:0ad3` | GPIO 6 | 顔認証カメラ (RGB+Depth) |
| SMI USB Display        | `090c:7680` | GPIO 8 | ディスプレイ (800x480)   |
| VIA Labs VL813 Hub     | `2109:2813` | -      | 内部USBハブ              |
```

つまり、実態としてはUSBハブの先に色々なデバイスがくっついたサブディスプレイに近い。IoT用のWindowsが搭載されている理由は操作用の組み込みソフトウェアを実装する上で都合が良かったからだろう。公式のSDKやDLL、サンプルソフトウェアなどはC#で書かれている。このようにWindows環境を前提とした設計なので、これを利用するなんらかのアプリケーションを開発する場合はおのずとC#が選定されると考えられる。

実際、検索するとWindows環境でマニュアル通りに色々動かしている様子はちらほらと見つかる。だが、僕はLinuxユーザなのであえて公式のDLLを利用せずにハードウェアを直接叩いてどこまで機能を引き出せるか試してみることにした。まず最初の関門は電源を入れるところだった。なんとこの端末、驚くべきことに電源ボタンがない。ドライバが入ったWindowsマシンに接続しないと電源が入らない仕様なのだ。

しかしLinuxであってもUSBケーブルで繋がっている以上は認識できる……。`lsusb`してみると`Microchip USB2734 Hub`が見えた。この端末のハブコントローラと思われる。ここでおもむろに会社支給のClaude Maxを起動し、ハブコントローラに対してコントロール転送を試みるスクリプトを書かせた。アドレス空間を満遍なくレジスタスキャンしてゼロ値ではない値を持つレジスタを特定させる。

次に公式DLLをClaudeに読み込ませてAPI仕様を特定する。`MchpUsbOpenID(VendorID=0x424, ProductID=0x2734)`で接続することが判明した。続いてUSBチップのメーカーの[公式リポジトリ](https://github.com/MicrochipTech/USB-Hub-Linux-Examples)からGPIOレジスタアドレス（`0x0830`/`0x0834`/`0x0838`）とアクセス方法（`bReq=0x03` 書込 / `bReq=0x04` 読取）を取得する。

最後にDirectionレジスタに出力ビットを設定し、Outputレジスタを HIGHに設定して`lsusb` すると、ここでついに端末の内蔵デバイス（Sony RC-S634、Intel RealSense D415 等）が認識された！　簡単に言っているようだがClaudeの力を借りても小一時間くらいはかかった。というわけで、まとめると以下の仕様となる。

```

| レジスタ      | アドレス | 読み取り    | 書き込み    | ビット意味                   |
| ------------- | -------- | ----------- | ----------- | ---------------------------- |
| **Direction** | `0x0830` | `bReq=0x04` | `bReq=0x03` | 1=出力, 0=入力               |
| **Output**    | `0x0834` | `bReq=0x04` | `bReq=0x03` | 1=HIGH, 0=LOW                |
| **Input**     | `0x0838` | `bReq=0x04` | -           | 現在のGPIO値（読み取り専用） |

USB コントロール転送パラメータ:

読み取り:
  bmRequestType = 0xC1 (Vendor, Device-to-Host, Interface)
  bRequest      = 0x04
  wValue        = レジスタアドレス
  wIndex        = 0
  wLength       = 4 (32bit、ビッグエンディアン)

書き込み:
  bmRequestType = 0x41 (Vendor, Host-to-Device, Interface)
  bRequest      = 0x03
  wValue        = レジスタアドレス
  wIndex        = 0
  data          = 4 bytes (32bit、ビッグエンディアン)

| ビット | GPIO番号 | 対応デバイス                         | マスク値     |
| ------ | -------- | ------------------------------------ | ------------ |
| bit 1  | GPIO 1   | ICカードリーダー (Sony RC-S634/UA)   | `0x00000002` |
| bit 2  | GPIO 2   | OCRカメラ (Ricoh)                    | `0x00000004` |
| bit 3  | GPIO 3   | タッチパネル (Futaba)                | `0x00000008` |
| bit 6  | GPIO 6   | 顔カメラ (Intel RealSense D415)      | `0x00000040` |
| bit 8  | GPIO 8   | LED / ディスプレイ (SMI USB Display) | `0x00000100` |
| 全ON   | -        | 全デバイス                           | `0x0000014E` |
```

これをもとにまたClaudeに書かせた起動スクリプトでパラメータを送りつけると、ようやくWindowsマシンなしで端末が起動してくれた。が、残念ながらディスプレイは点灯しない。ディスプレイだけは最後まで使えなかった。どうやらこれだけはWindows側で外部ディスプレイとして認識されている状態が必須らしい。
